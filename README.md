## How I Work

- **Dependable boundaries.** Explicit contracts between frontend, backend, and external services. When a boundary stays vague, the complexity behind it ends up in product code.
- **Quality belongs in the ticket.** Accessibility, tests, and performance go in the ticket, the review, and the release checklist — anything scheduled for "afterwards" gets cut when the deadline moves.
- **Product context first.** Who depends on this, and what happens to them when it breaks? That answer constrains the design more than the framework does.
- **AI with guardrails.** I use AI for research, scaffolding, and the repetitive parts of delivery. Validation, tests, and security boundaries stay explicit, and a person still reads the diff.
